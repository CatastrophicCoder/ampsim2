# Verification Specification

Every block and the full chain are verified against ngspice. This document defines the reference
types, test signals, presets, metrics, tolerances and report format.

---

## 1. Reference types

| Name | What | Purpose |
|---|---|---|
| **F** (full) | `reference/spice/jcm800_2203.cir` unchanged | Ground truth for the whole amp |
| **P** (partitioned) | SPICE block testbenches using the same partition and J-Thevenin junctions as the engine (`SPEC.md` §4), chained: each block's SPICE testbench is driven by the previous block's SPICE output | Isolates engine implementation error from partition error |
| **E** | Engine (via `ampwav`), single block or full chain | Under test |

Errors reported:
- **Block-exact error**: E_k (engine block k driven by P_{k−1} output) vs P_k. Should be small; it
  measures WDF/solver correctness.
- **Partition error**: P (chained) vs F at the same node. Purely a property of the partition choices.
- **Total error**: E (full chain) vs F.

Feedback and supply exceptions:
- B5 and B6 are coupled by the NFB, and all blocks are coupled to B7. The P reference therefore
  simulates **B56+B7 as one testbench** (driven by the J4 source), with instantaneous feedback and a
  directly connected supply. The engine's one-sample delays (NFB, supply) appear as part of the
  block-exact error of B56.
- For isolated unit verification, two open-loop testbenches exist: **B5-open** (R22 driven by the
  recorded speaker voltage from the B56 run, as an ideal source) and **B6** (driven by the recorded
  PI open-circuit outputs). Supply node voltages in these are the recorded B56 supply waveforms.
- Blocks B12, B3 and B4 in P use the supply node voltages from the corresponding F run as ideal recorded
  sources (or constants from the DC table for M1–M2).

## 2. Testbench construction
- Testbenches live in `harness/testbenches/` and are generated by a script from the reference netlist
  plus a per-block description (list of kept elements, inserted J-Thevenin sources, probes). Generated
  files are committed so they can be read and diffed.
- Each testbench exposes the block's input source, its open-circuit output node and the internal nodes
  needed for debugging.
- Sanity check (M0): each testbench's DC operating point at its internal nodes matches F within 0.5 %.
- Driving recorded signals into ngspice: prefer an XSPICE file source or PWL-from-file if available in
  the installed ngspice (check `ngspice -v` and the manual); otherwise generate an inline PWL include
  file. Cache renders keyed by a hash of (testbench text, parameters, input signal).
- Transient settings: `tran` with max step = 1/384000 s and `linearize` to that exact step (or the
  `option interp` approach used in `spice_tools.py`), so that SPICE output samples align 1:1 with the
  engine's samples at 384 kHz. Both start from the DC operating point; no time alignment is applied.
  The comparison reports the best lag within ±2 samples as a diagnostic; a non-zero best lag is a bug.
  Implementation (DECISIONS D-014): XSPICE filesource input plus a dummy PULSE source with a corner at
  every sample, so every sample instant is a simulator time point; ngspice RELTOL is set in
  `harness/config.py`.

## 3. Test signals (generated at 384 kHz by `harness/signals.py`)

| ID | Signal | Notes |
|---|---|---|
| SIN | Sines at 100 Hz, 1 kHz, 5 kHz; 150 ms each | Amplitudes per block, see §4 |
| SWP-lo | Exponential sweep 20 Hz–20 kHz, 2 s, small-signal level, then 50 ms silence | Frequency response in the linear region (per-bin Y/X, D-014) |
| SWP-hi | Same sweep at nominal block level | Nonlinear frequency behaviour |
| TT | Two tones 220 Hz + 330 Hz, equal level, 300 ms | Intermodulation (power-chord-like) |
| BURST | 1 kHz: 50 ms low, 300 ms high (+30 dB), 300 ms low | Blocking / bias-shift recovery |
| STEP | 0 → nominal DC-free pulse train (5 ms on/off) | Transient settling |
| DI | Owner's DI guitar recordings in `reference/di/` (mono WAV), resampled to 384 kHz with `scipy.signal.resample_poly`, scaled by `inputVoltsPerFullScale` | 5–10 s excerpts; most representative test |

DI recordings are not included in the repository by default (owner provides them; see
`reference/di/README.md`). Tests that need them are skipped with a clear message when absent.

## 4. Levels and presets

Block input amplitudes (volts peak at the junction source):
| Block | Small | Nominal | Hot | Overdrive |
|---|---|---|---|---|
| B12 (guitar input) | 0.01 | 0.1 | 0.5 | 2.0 |
| B3 (J2 source) | 0.1 | 1 | 10 | 50 |
| B4 (J3 source, linear) | — | 1 | — | — |
| B56 (J4 source) | 0.1 | 1 | 5 | 20 |

With the P chaining, realistic levels for downstream blocks come from the upstream SPICE outputs; the
table is for the standalone sine tests. In standalone tests the signal rides on the junction source's DC operating
point (the testbench's `Vin` DC value), for SPICE and the engine alike (DECISIONS D-022).

Full-chain presets (tone controls 0.5, presence 0.5 unless stated):
| Preset | Preamp Volume | Master | Input |
|---|---|---|---|
| CLEAN | 0.2 | 1.0 | 25 mV peak 1 kHz (≈ 100 W in SPICE) |
| CRUNCH | 0.6 | 0.3 | 300 mV peak 220 Hz, DI clips |
| DRIVE | 1.0 | 0.3 | 300 mV peak 220 Hz, DI clips |
| TONE-x | 0.6 | 0.3 | Treble/Middle/Bass each at {0, 0.5, 1}, SWP-lo |

## 5. Unit-level device verification

### 5.1 DC sweeps (SPICE → CSV in `tests/data/`, used by Catch2)
- 12AX7 alone: Vpk 0–400 V (5 V steps) for Vgk ∈ {0, −0.5, −1, −1.5, −2, −3, −4} V; grid current for
  Vgk ∈ {−1, −0.5, 0, 0.25, 0.5, 1, 2, 5} V at Vpk = 200 V. Record Ip and Ig.
- EL34 alone: Vpk 0–600 V (10 V steps) for Vsk ∈ {250, 400, 490} V and Vgk ∈ {0, −10, −20, −30, −40,
  −46, −50, −60} V; grid current for Vgk ∈ {−5, 0, 1, 5, 10} V. Record Ip, Is, Ig.
- Tolerance: 0.1 % relative or 1 nA absolute, whichever is larger.
- Generated by `python -m harness.device_sweeps` into `tests/data/{12ax7,el34}_{plate,grid}.csv`
  (DECISIONS D-019). The EL34 grid-current sweep runs at Vpk = Vsk = 400 V. `ip` excludes tubes.lib's
  1 GΩ Rcp (the engine omits it, WDF_DESIGN §3); `ip_terminal` is the SPICE terminal current.

### 5.2 Jacobians
Analytic vs central finite differences at all sweep points: 1e−5 relative (skip points where the
derivative is below 1e−12 A/V). Points at Vpk = 0 are skipped as well: there E1 = 0 and the plate
current (∝ E1^ex, ex = 1.4) is once but not twice differentiable, so a central difference across it has
an error ∝ h^0.4 (the analytic derivative there is 0). `tests/test_triode.cpp` checks the remaining
7 × 80 plate-curve points and the 8 grid-current points.

### 5.3 Adaptors
See `WDF_DESIGN.md` §5.5.

## 6. Metrics

| Metric | Definition |
|---|---|
| ESR | 10·log10( Σ(y−ŷ)² / Σy² ) in dB over the analysed window (whole signal unless stated), where y and ŷ are each the node voltage minus its own DC operating point (its value at t = 0; every signal starts there). Static DC offsets are scored by the DC error check; bias shifts during the signal are scored here (DECISIONS D-018). Best lag and the SWP-lo magnitude response use the same signals |
| Harmonic diff | Levels of harmonics 1–10 (Hann window, last 40 ms of each sine), difference in dB; only harmonics above −80 dBc are scored |
| THD diff | THD (10 harmonics) difference in percentage points |
| Magnitude response | Engine response from SWP-lo (deconvolved) vs SPICE AC analysis; max abs dB error per band |
| DC error | Node voltages after `reset()` vs SPICE `op`, relative |
| Power | Mean power into 16 Ω over the last 40 ms |
| Newton stats | Median / max iterations, failure count |
| Best lag | Lag in ±2 samples minimising ESR (diagnostic) |

## 7. Tolerances (initial; changes require an entry in DECISIONS.md and owner approval)

| Check | Tolerance |
|---|---|
| Device DC sweeps | 0.1 % / 1 nA |
| Linear block magnitude (B4) | ≤ 0.1 dB (20 Hz–10 kHz), ≤ 0.3 dB (10–20 kHz) |
| Linear block time-domain ESR | ≤ −60 dB |
| Knob jump (SPEC §6.2: each knob 0→1 in 10 ms during a 1 kHz tone) | No NaN/Inf; ESR vs SPICE with time-varying pots on the same smoothed rotation trajectory ≤ −40 dB over the sweep and the 20 ms after it (D-025) |
| DC operating point (any block) | ≤ 0.5 % per node (EL34 currents: ±1 mA plate, ±0.3 mA screen) |
| Block-exact ESR, nonlinear, Small/Nominal/Hot | ≤ −40 dB |
| Block-exact ESR, Overdrive | ≤ −30 dB |
| Block-exact harmonics 2–5 | within 0.5 dB |
| Partition error at y (M3) | ≤ −26 dB sines, ≤ −20 dB DI (report; triggers upgrade path if exceeded) |
| Total, CLEAN power | ±5 % of SPICE, THD ±0.5 pp |
| Total, DRIVE/CRUNCH ESR | ≤ −20 dB; harmonics 2–9 within 1.5 dB |
| NFB amount | ±0.5 dB at 100 Hz / 1 kHz / 5 kHz |
| Stability | 60 s silence at max settings: |out| < 1 mV, no growth |
| Newton | 0 failures on the standard signal set |

ESR on heavily clipped signals is sensitive to tiny timing differences at sharp edges. If a check fails
mainly because of edge timing, also report ESR after a 5 kHz low-pass on both signals and the harmonic
comparison, and raise it with the owner rather than loosening tolerances silently.

## 8. Reports

`python -m harness.compare --block <id> --preset <id> --milestone M<n>` writes
`harness/reports/M<n>/<YYYYMMDD>_<block>_<preset>.md` plus PNGs:
- Summary table: every check, measured value, tolerance, PASS/FAIL.
- Waveform overlay (F/P/E) and error trace for the most demanding signal.
- Harmonic bar chart, magnitude response overlay, spectrogram of E vs P for DI.
- Newton statistics and the per-sample CPU cost of the block (from the CLI's timing output).
- Git commit hash of the engine and hash of the testbench/netlist used.

Reports are committed. The milestone report is what the owner reviews.

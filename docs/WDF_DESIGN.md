# WDF Design Notes: Math and Algorithms

This document gives the equations the engine implements. Where `chowdsp_wdf` already provides an
element (resistor, capacitor, inductor, resistive voltage source, series/parallel/R-type adaptors),
use the library's implementation; the equations here are for understanding, verification and for the
parts the library does not provide (tube roots, MNA scattering computation, supply model).

---

## 1. Wave variables and conventions

Per port with port resistance R (voltage waves):

```
a = incident wave (towards the element),  b = reflected wave (from the element)
v = (a + b) / 2          i = (a − b) / (2R)          (i flows into the element's + terminal)
b = a − 2R·i             v = a − R·i
```
Confirm against `chowdsp_wdf` at the pinned version (sign of current, which side is "incident") before
writing custom elements, and add a unit test that a custom resistor written with these equations
behaves identically to the library's resistor.

## 2. Linear elements (bilinear / trapezoidal discretisation, T = 1/fs)

| Element | Port resistance | Reflection |
|---|---|---|
| Resistor R | R | b = 0 |
| Capacitor C | T / (2C) | b[n] = a[n−1] |
| Inductor L | 2L / T | b[n] = −a[n−1] |
| Resistive voltage source (Vs, Rs) | Rs | b = Vs |
| Ideal voltage source (root only) | — | b = 2Vs − a |

Frequency warping of the bilinear transform is negligible below 20 kHz at fs ≈ 384 kHz (about 0.2 % at
20 kHz), which is why verification runs at the oversampled rate.

## 3. Device equations and Jacobians

These must match `reference/spice/tubes.lib` exactly. Numerically stable helpers:

```
softplus(u) = u > 30 ? u + log1p(exp(−u)) : (u < −30 ? exp(u) : log1p(exp(u)))
sigmoid(u)  = 1 / (1 + exp(−u))          (derivative of softplus)
```

### 3.1 Triode (12AX7), ports G = (g, k) and P = (p, k)

```
s   = sqrt(kvb + Vpk²)
u   = kp · (1/mu + Vgk / s)
E1  = Vpk · softplus(u) / kp
Ip  = E1 > 0 ? 2 · E1^ex / kg1 : 0                         (plate → cathode)

∂E1/∂Vgk = Vpk · sigmoid(u) / s
∂E1/∂Vpk = softplus(u)/kp − sigmoid(u) · Vgk · Vpk² / s³
∂Ip/∂x   = (2 · ex · E1^(ex−1) / kg1) · ∂E1/∂x           (0 when E1 ≤ 0)
```

Grid current: ideal diode (Is, n, Vt) in series with Rs = rgi + 1 Ω (the SPICE diode's RS=1), from grid
to cathode. Closed form with the Wright omega function ω (ω(z) = W(e^z)):

```
Ig(Vgk)   = (n·Vt / Rs) · ω(z) − Is,     z = ln(Is·Rs / (n·Vt)) + (Vgk + Is·Rs) / (n·Vt)
dIg/dVgk  = 1 / (Rs + n·Vt / (Ig + Is))  =  ω / (Rs·(1 + ω))
```
ω is evaluated to double precision (`engine/src/devices/WrightOmega.h`: initial guess plus
Fritsch–Shafer–Crowley iterations; DECISIONS D-028).
Is = 1e−9 A, n = 1, Vt = k·T/q = 25.8649170 mV (27 °C, ngspice default, with ngspice's constants
k = 1.38064852e−23, q = 1.6021766208e−19). The SPICE 1 GΩ resistors (Re1, Rcp) are omitted. Port
currents: i_G = Ig, i_P = Ip.
SPICE detail not replicated (D-019): below −3·n·Vt across the junction, ngspice's diode uses the
reverse-bias form −Is·(1 + (3·n·Vt / (e·Vd))³) instead of the exponential; the difference is at most
5e−11 A (at −3·Vt), far below the 1 nA device tolerance.

### 3.2 Pentode (EL34, with the repository screen modification), ports G1 = (g, k), G2 = (s, k), P = (p, k)

```
Vs'  = max(Vsk, 1e−3)
u    = kp · (1/mu + Vgk / Vs')
E1   = Vs' · softplus(u) / kp
F    = E1 > 0 ? 2 · E1^ex : 0
Ip   = (F / kg1) · atan(Vpk / kvb)
Is   = F · ( 1/kg2 + (1.5707963 − atan(max(Vpk, 0) / kvb)) / kg1 )    (tubes.lib's literal for π/2)
Ig   = diode as in 3.1 with Rs = 1000 Ω + 1 Ω

∂E1/∂Vgk = sigmoid(u)
∂E1/∂Vsk = softplus(u)/kp − sigmoid(u) · Vgk / Vs'          (0 when Vsk < 1e−3)
∂F/∂x    = 2 · ex · E1^(ex−1) · ∂E1/∂x
∂atan(Vpk/kvb)/∂Vpk = (1/kvb) / (1 + (Vpk/kvb)²)
```
Note: as in SPICE, `atan(Vpk/kvb)` is not clamped in the plate equation, so Ip would go negative if the
plate fell below the cathode. Replicate SPICE exactly; log it if it ever happens in the harness.

Matched-pair equivalent (B6): multiply Ip, Is, Ig and all their derivatives by 2.

### 3.3 Verification of device code
- DC sweep tables generated by SPICE (`VERIFICATION.md` §5.1) compared within 0.1 % (relative) or 1 nA
  (absolute), whichever is larger.
- Analytic Jacobian vs central finite differences (h = 1e−6 · max(1, |V|)) within 1e−5 relative.

## 4. Multiport nonlinear root: Newton solver

For a root with N ports, each port k has an unknown port voltage v_k and a device current i_k(v) (from
§3, into the port's + terminal; it may depend on several port voltages). The linear network below the
root (the R-type adaptor and its elements) seen from the N root ports is an exact N-port Thevenin
equivalent: v = v_oc − Z·i, where v_oc is a linear function of the elements' reflected waves and Z is
the N×N resistance matrix of the network with every element replaced by its port resistance
(DECISIONS D-028):

```
f(v) = v + Z · i(v) − v_oc = 0
J    = I + Z · ∂i/∂v
v   ← v − J⁻¹ f                                           (Newton step)
```
After convergence the node voltages follow from the element waves and the root currents, and each
element receives the incident wave 2·v_port − b_element. Both maps come from one MNA computation
(`mna::rootTransfer`: node voltages = Xe·b − Xr·i). If the root ports are uncoupled (Z diagonal), this
is the familiar form f_k = v_k + R_k·i_k − a_k with R_k = Z_kk and a_k = v_oc,k; in the triode blocks
the ports share the cathode network and Cgp, so Z has off-diagonal terms and the full matrix is used.

Port maps:
| Block | N | Ports |
|---|---|---|
| B12 | 4 | V1a (g1a−k1a, p1a−k1a), V1b (w1−k1b, p1b−k1b) |
| B3 | 4 | V2a (g2a−k2a, p2a−k2a), V2b (p2a−k2b, bpX−k2b) |
| B5 | 4 | V3a (g3a−k3, p3a−k3), V3b (g3b−k3, p3b−k3) |
| B6 | 6 | side A (g−k, s−k, p−k), side B (g−k, s−k, p−k); cathodes at ground |

Algorithm (per sample):
1. Initial guess: linear extrapolation from the two previous solutions, v = 2·v[n−1] − v[n−2]
   (DECISIONS D-029; the plain warm start v[n−1] failed at V1b's exit from cutoff at 5 kHz 2 V).
2. Up to `maxIter` (default 12) iterations; per-port step limit (default 2 V for grid ports, 20 V for
   screen/plate ports) to keep the exponential terms well-behaved. The step is scaled uniformly so that
   no port exceeds its limit (this keeps the Newton direction).
3. Convergence when ‖Δv‖∞ < 1e−9 · max(1, ‖v‖∞) or ‖f‖∞ < 1e−9 V.
4. If an iteration increases ‖f‖, halve the step (up to 4 times) before accepting it.
5. If not converged after `maxIter`: keep the best iterate (lowest ‖f‖), increment the failure counter.
6. Linear solve: fixed-size Gaussian elimination with partial pivoting (template on N; no heap, no
   Eigen in the audio path).

Statistics (median/max iterations, failure count) are exposed for the harness.

Later optimisations (M6, only with harness evidence): chord method (reuse J for several iterations),
lookup tables for E1/softplus/omega, higher-order predictors.

## 5. R-type adaptors: scattering matrix from the circuit

R-type adaptors are needed where the topology is not series/parallel decomposable: the tone stack (B4)
and every block whose nonlinear root has several ports sharing nodes (B12, B3, B5, B6).

### 5.1 Definition-based computation (reference implementation)
For an adaptor with N ports, model each port n as a Thevenin source (voltage a_n in series with R_n)
connected to the adaptor's internal topology (ideal wires between the ports' terminals and internal
nodes). The scattering matrix S maps incident to reflected waves, b = S·a. Compute it column by column:

```
for j in 1..N:
    set a_j = 1, all other a = 0
    solve the linear circuit (MNA) for every port voltage v_n
    column j of S:  S[n][j] = 2·v_n − a_n
```
Factor the MNA matrix once and back-substitute N times. Implemented in C++ in double-double arithmetic
(`engine/src/mna/`, D-026) and in Python in exact rationals (`harness/mna.py`); a unit test compares both
for each adaptor.

The closed-form MNA expression from Werner et al., "Wave Digital Filter Adaptors for Arbitrary
Topologies and Multiport Linear Elements" (DAFx-15), S = I + 2·[0 R]·X⁻¹·[0 I]ᵀ, is equivalent; if used,
verify its sign convention against the definition-based method above.

### 5.2 Adapted (up-facing) port
For an adaptable R-type adaptor whose up-port faces a parent, choose the up-port resistance so the
up-port is reflection-free (S[up][up] = 0): R_up = the resistance seen into the adaptor from the up-port
with all other ports replaced by their port resistances (sources zeroed). Compute with the same MNA.

### 5.3 Root-facing ports of a multiport nonlinearity
When the R-type adaptor sits directly below a multiport nonlinear root, the root-facing port
resistances are free positive parameters (the Newton solve is implicit). With the root equation in
Thevenin form (§4, D-028) they cancel out: the root ports are eliminated and the Newton iteration works
on the port voltages with the resistance matrix Z.

### 5.4 Parameter changes
When a pot or any adaptable element changes, recompute the affected port resistances, the S matrix and
any up-port resistance. Rate-limit per `SPEC.md` §6.2. Run S recomputation in the audio thread only if
its measured cost fits the budget; otherwise compute on a worker thread into a double buffer and swap
atomically at a sample boundary (document the choice).

### 5.5 Sanity checks for every adaptor (unit tests)
- An R-type adaptor built for a pure series (or parallel) 3-port matches the library's series
  (parallel) adaptor to 1e−12.
- Losslessness (for adaptors with only ideal wires): with G = diag(1/R), the matrix Sᵀ·G·S − G is zero
  to 1e−9 relative.
- Up-port reflection-free condition holds to 1e−12.

## 6. Junctions (J-Thevenin)

Downstream tree: an adaptable resistive voltage source with resistance R_th and voltage v_oc[n], where
v_oc[n] is the upstream block's open-circuit output voltage at the same sample (upstream processed
first). The upstream tree has its output node unloaded.

J4 (master wiper): v_oc(y) is the wiper voltage with no PI load. R_th4 is the resistance seen into the
wiper with the J3 source shorted, from a DC MNA solve of the B4 network (recompute on parameter change).
Document whether the reactive part is ignored (default: ignored; check partition error in M3/M4).

J5 (PI plates): R_thA and R_thB from the M0 SPICE measurement (constants). The LTP output resistance
depends on the other half and the tail; the constants are linearised at the operating point.

Upgrade path if partition error exceeds tolerance: (a) frequency-dependent source impedance (add the
dominant reactive element), (b) merge stages under one multiport root.

## 7. Supply model (B7)

States: v_ct (C23), i_L (choke), v_scr (C22), v_X (C21b), v_A (C21a).
Inputs (previous sample): I_ct (sum of all EL34 plate currents through the OT centre tap),
I_scr (sum of EL34 screen currents), I_X (V2a plate + V2b plate + both PI plates),
I_A (V1a plate + V1b plate).

```
C23 · dv_ct/dt  = (Vht − v_ct)/Rsrc − i_L − I_ct
L   · di_L/dt   = v_ct − Rch·i_L − v_scr
C22 · dv_scr/dt = i_L − (v_scr − v_X)/R29 − I_scr
C21b· dv_X/dt   = (v_scr − v_X)/R29 − (v_X − v_A)/R8 − I_X
C21a· dv_A/dt   = (v_X − v_A)/R8 − I_A
```
Discretise with the trapezoidal rule (precompute the discrete matrices in `prepare`). DC init: solve
the same equations with all derivatives zero, iterating with the blocks' DC currents (fixed point).
The trees read v_ct, v_scr, v_X, v_A as ideal (time-varying) supply sources.

Inside B6 the OT centre tap sits at v_ct. The SPICE model has C23 directly at the centre tap; the
one-sample coupling through B7 is the approximation. Check it in M4 (clean-power and sag acceptance).

## 8. Oversampling and aliasing

The engine itself does not resample. The plugin wraps it with `juce::dsp::Oversampling`; the harness
runs it directly at 384 kHz. Report aliasing in M5 with a high-frequency sine sweep (e.g. 1–20 kHz at
high gain) and a spectrogram, comparing 4x/8x/16x.

### Magnitude error

The error is largest towards 20 kHz, where the bilinear transform's frequency warping (≈ 0.2 % at 20 kHz,
WDF_DESIGN §2) matters most; worst 0.078 dB against 0.3 dB allowed. Master scales v_oc(y) by a
frequency-independent ratio (the wiper is unloaded and VR2's total is fixed), so the dB error is the same
at every Master setting. Plot: `20261013_b4_tonestack_magnitude_error.png`.

### Knob jumps

| Case | ESR | Peak error / reference peak | Error energy > 5 kHz vs tone |
|---|---|---|---|
| Treble | −58.4 dB | 2.8e-3 | −62.4 dB |
| Middle | −58.2 dB | 2.4e-3 | −66.3 dB |
| Bass | −67.1 dB | 7.9e-4 | −97.6 dB |
| Master | −47.2 dB | 5.4e-3 | −50.1 dB |
| All four | −46.1 dB | 6.4e-3 | −48.8 dB |

The error comes from the rate-limited matrix updates (every 32 samples, a staircase in the pot values):
with an update every sample (a temporary build, not committed) the same cases give −88 to −92 dB, which
also shows that the SPICE reference and the engine's smoothing agree.

### Cost (`amp2203_bench b4`)

| Quantity | Value |
|---|---|
| Static knobs | 31.7 ns/sample (1.2 % of the 2.6 µs/sample budget at 384 kHz) |
| One scattering-matrix update (12 ports, double-double, D-026) | ≈ 7.3 µs |
| Knobs moving continuously (update every 32 samples) | 262–275 ns/sample (≈ 10 % of the budget, only while a knob moves) |

The update fits the audio thread, so there is no worker thread (WDF_DESIGN §5.4); kParamUpdateInterval
stays 32 (D-027).

### R_th4 for J4

The engine's `rth4` (D-015 formula from the smoothed knobs) matches the testbench formula as evaluated by
ngspice to 2e-16 relative at 11 settings.
